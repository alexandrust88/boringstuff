== Overview

Dashboard:: *Cilium Deep Insights v2 (AKS / Fleet)*
Cluster filter default:: `cass-*`
Hubble metrics:: Not available (AKS-managed Cilium)

== Datadog Agent Configuration -- What to Enable

=== Cilium OpenMetrics Check (cilium-agent metrics)

Deploy via Datadog Agent DaemonSet annotations or Helm values:

[source,yaml]
----
# datadog-agent helm values
datadog:
  confd:
    cilium.yaml: |-
      ad_identifiers:
        - cilium-agent
      init_config:
      instances:
        - openmetrics_endpoint: "http://%%host%%:9962/metrics"
          namespace: cilium
          metrics:
            - ".*"
          raw_metric_prefix: ""
          send_distribution_buckets: false
          send_monotonic_counter: true
----

=== Cilium Operator Check

[source,yaml]
----
    cilium_operator.yaml: |-
      ad_identifiers:
        - cilium-operator
      init_config:
      instances:
        - openmetrics_endpoint: "http://%%host%%:9963/metrics"
          namespace: cilium.operator
          metrics:
            - ".*"
----

=== Kubernetes State Metrics Core (KSM)

[source,yaml]
----
datadog:
  kubeStateMetricsCore:
    enabled: true
----

=== System Checks (enabled by default)

Auto-enabled on the Datadog Agent DaemonSet:

* `system.cpu.*`, `system.mem.*`, `system.disk.*`, `system.net.*`, `system.load.*`, `system.uptime`
* `tcp_queue.*`, `oom_kill.*`

=== Kubelet Check (enabled by default)

Auto-collects: `kubernetes.cpu.*`, `kubernetes.memory.*`, `kubernetes.pods.*`, `kubernetes.containers.restarts`

== Metrics Reference by Dashboard Section

=== Security Posture

[cols="2,3,2", options="header"]
|===
| Metric | What It Tells You | Alert When

| `cilium.endpoint.count`
| Total managed endpoints
| Sudden drop = pods not getting networked

| `cilium.policy.endpoint_enforcement_status`
| Endpoints by enforcement mode
| `policy_enforcement_status:none` > 10% of total

| `cilium.drop_count.count`
| Packets dropped by datapath
| Drop-to-forward ratio > 1%

| `cilium.forward_count.count`
| Packets forwarded
| Flatline = network issue
|===

Tags:: `kube_cluster_name`, `host`, `reason`, `direction`, `policy_enforcement_status`

=== Agent / Operator Health

[cols="2,3,2", options="header"]
|===
| Metric | What It Tells You | Alert When

| `cilium.openmetrics.health`
| Agent scrape health (service check)
| Status != OK

| `cilium.controllers.failing.count`
| Failing internal controllers
| > 0

| `cilium.unreachable.nodes`
| Nodes this agent can't reach
| > 0

| `cilium.policy.count`
| Loaded network policies
| Unexpected drop

| `cilium.controllers.runs.count`
| Controller executions by `status`
| `status:failure` sustained

| `kubernetes.containers.restarts`
| Agent/operator pod restarts
| > 2 in 15m (filter `kube_container_name:cilium-agent`)
|===

=== Drops & Network Traffic (SRE Critical)

[cols="2,3,2", options="header"]
|===
| Metric | What It Tells You | Alert When

| `cilium.drop_count.count`
| Drop rate by `reason` and `direction`
| Anomaly band breach, new `reason` appearing

| `cilium.forward_bytes.count`
| Bytes forwarded (ingress/egress)
| Asymmetry or flatline

| `cilium.forward_count.count`
| Packets forwarded (ingress/egress)
| Sudden change
|===

IMPORTANT: Key drop reasons to watch: `POLICY_DENIED`, `CT_TRUNCATED_OR_INVALID_HEADER`, `UNSUPPORTED_L3_PROTOCOL`

=== eBPF & Datapath Health (Critical)

[cols="2,3,2", options="header"]
|===
| Metric | What It Tells You | Alert When

| `cilium.bpf.map_pressure`
| BPF map fill ratio (0.0--1.0)
| > 0.75 warn, > 0.9 critical

| `cilium.bpf.maps.virtual_memory.max.bytes`
| Memory used by BPF maps
| Sustained growth

| `cilium.bpf.progs.virtual_memory.max.bytes`
| Memory used by BPF programs
| Sustained growth

| `cilium.bpf.map_ops.count`
| Map operations, filter `outcome:fail`
| Any failures

| `cilium.datapath.conntrack_gc.entries`
| Conntrack table size per node
| Approaching kernel limit

| `cilium.datapath.conntrack_gc.duration.seconds.*`
| GC cycle time (sum/count for avg)
| Avg > 1s
|===

WARNING: Critical map names: `cilium_ct4_global`, `cilium_ct_any4_global`, `cilium_ipcache`, `cilium_policy_*`

== Importing the Dashboard

[source,bash]
----
# Export DD keys
export DD_API_KEY="<your-api-key>"
export DD_APP_KEY="<your-app-key>"
export DD_SITE="datadoghq.eu"  # or datadoghq.com

# Import
curl -X POST "https://${DD_SITE}/api/v1/dashboard" \
  -H "Content-Type: application/json" \
  -H "DD-API-KEY: ${DD_API_KEY}" \
  -H "DD-APPLICATION-KEY: ${DD_APP_KEY}" \
  -d @cilium_stuff/datadog-custom-dashboard.json
----

Or import via Datadog UI: *Dashboards > New Dashboard > Import Dashboard JSON*.

== Troubleshooting

=== No data on Cilium widgets

[source,bash]
----
# Verify agent is scraping cilium
kubectl exec -n datadog <agent-pod> -- agent status | grep cilium

# Verify cilium metrics endpoint
kubectl exec -n kube-system ds/cilium -- curl -s localhost:9962/metrics | head -20
----

=== Metrics appear with wrong names

Check OpenMetrics V2 is being used (default in Agent 7.x). V1 uses different naming.

=== Missing operator metrics

[source,bash]
----
kubectl exec -n kube-system deploy/cilium-operator -- curl -s localhost:9963/metrics | head -20
----

=== Node Health section empty

Ensure KSM Core check is enabled and `system.*` checks are running on all nodes.
